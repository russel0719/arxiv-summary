# 주간 논문 → 프로젝트 적용 제안 — 작업 컨텍스트

이 지침은 그 주의 arXiv 일일 다이제스트(이미 선별·요약·태깅된 논문)와
`project_profiles.md`(내 프로젝트들의 task·스택·관심 태그·**개선 여지**)를 교차 분석해,
**지금 당장 착수할 만한 소수의 적용안**을 깊게 제안하는 리포트를 만드는 규칙이다.

**핵심 원칙: 적게, 깊게, 실행가능하게.** 관련 있는 걸 모두 나열하지 말고,
정말 우선순위 높은 소수만 골라 사람이 바로 착수할 수 있을 만큼 구체적으로 쓴다.

## 입력

1. **이번 주 일일 다이제스트** — 셸이 넘겨주는 `reports/YYYY/MM/report_DD.md`들.
   각 논문 항목에 제목·arxiv url·한줄요약·핵심기여·실무관련성·태그가 있다.
2. **프로젝트 프로파일** — `project_profiles.md`. 프로젝트별 목적/Task/스택/관심 태그/개선 여지.

(이 리포트는 비공개 산출물이므로 프로젝트 경로·모델·repo명을 그대로 써도 된다 —
 일일 다이제스트의 task 추상화 규칙은 여기 적용되지 않는다.
 언어·git 등 공통 규칙은 repo 루트 `CLAUDE.md` 참조.)

## 1단계 — 후보 매칭

- 이번 주 **모든 논문**을 프로파일과 대조해 후보를 만든다. 매칭 신호(강→약):
  개선 여지 직접 대응 > 태그 교집합 > 스택·task 인접성.
- 한 논문이 여러 프로젝트에 걸치면 각각 후보로. **억지 매칭 금지** — 관련 없으면 버린다.

## 2단계 — 실행 추천 선정 (엄격)

후보 중 아래 바(bar)를 만족하는 것만 **실행 추천**으로 승격한다:

1. **병목 직격** — 프로젝트 "개선 여지"의 핵심 병목을 정면으로 해결/개선한다.
2. **코드 가용** — 공식 코드가 공개돼 있고 라이선스가 사용 가능하다. finalist는
   WebSearch/WebFetch로 실제 확인하고, 확인 안 되면 "불명"으로 표기하고 승격에 신중히
   판단한다(재구현 부담을 리스크에 명시).
3. **방법 명확** — 우리 스택의 어느 모듈/단계에 무엇을 추가·교체·제거하는지 구체적으로 그려진다.
4. **착수 용이(가점)** — 대규모 학습·실데이터 없이 착수 가능하면 우선순위를 올린다.

**개수 상한: 실행 추천은 최대 5건, 권장 3건.** 기준 (1)·(3)이 약하면 올리지 않는다.
강한 후보가 3건 미만이면 **억지로 채우지 않는다** — 적으면 적은 대로 둔다.

## 3단계 — 나머지 처리

- 승격 못 했지만 관련은 있는 후보 → **"후보 풀"에 한 줄**로 남긴다
  (미달 사유 명시: 코드없음 / 데이터필요 / 효과불확실 / 통합비용과다 등).
- 어디에도 안 맞는 논문 → 조용히 건너뛴다.

## 우선순위 (실행 추천 정렬)

- **전역 우선순위**로 정렬한다(프로젝트 무관). 최상단이 "이번 주 첫 착수 대상".
- 우선순위 = 병목 임팩트 × 착수 용이성.
- **난이도** 라벨: 무학습·헤드/어댑터만 학습 = 낮음, 백본 교체·모듈 추가학습 = 중간,
  대규모 재학습·데이터 구축 = 높음.

## 출력 형식 (고정 — 매주 동일 포맷)

셸이 지정한 출력 경로(`~/workspace/.meta/paper-match/weekly_match_YYYY-MM-wN.md`)에 아래 형식으로 저장한다.
제목의 주차 표기는 셸이 넘겨준 라벨(예: `2026년 7월 3째주`)을 그대로 쓴다.

```
# 주간 논문 → 프로젝트 적용 제안 — <YYYY년 M월 N째주> (KST)

- **스캔**: N개 리포트 / 논문 M편 → 매칭 후보 K건 → 실행 추천 T건
- **선정 기준**: 병목 직격 + 공개코드 + 방법 명확 + 착수 용이

## 🎯 이번 주 실행 추천  (전역 우선순위 순, 최대 5)

### 1. [논문 제목](arxiv url) → <프로젝트 경로> · 난이도: 낮음/중간/높음
- **왜 지금**: <이걸 지금 최우선으로 두는 한 줄 근거>
- **대상·병목**: <어느 프로젝트의 어느 개선 여지를 겨냥>
- **적용 방법**: <우리 스택의 어느 모듈/단계에 무엇을 추가·교체·제거 — 단계로 구체화>
- **코드·자료**: [repo](url) · 라이선스 / 없으면 "재구현 필요" 명시
- **예상 효과**: <논문 정량 수치 + 우리 맥락 기대. "좋아진다"류 금지, 근거 제시>
- **검증 방법**: <어떤 지표·어떤 데이터셋으로 개선을 확인할지>
- **리스크·전제**: <라이선스·데이터·환경(예: mamba-ssm 재빌드) 등 착수 전 확인사항>
- **태그**: <kebab-case 3~5개>

(…최대 5건까지 우선순위 순으로 반복. 항목 사이 `---` 구분.)

## 📋 후보 풀 (참고, 한 줄)

- <프로젝트 경로>: [논문](arxiv url) — <한 줄 이유> (미달: 코드없음 / 데이터필요 / 효과불확실 …)
(관련 있으나 실행 추천 바를 못 넘은 매칭만. 없으면 이 섹션 생략.)
```

- 실행 추천이 0건이면, 헤더 + "이번 주 당장 착수할 만한 적용안 없음" 한 줄 + (있으면) 후보 풀만 남긴다.
